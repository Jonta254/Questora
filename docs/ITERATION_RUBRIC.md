# Questora iteration rubric

After every review or research pass, answer these questions before changing the product:

1. What real user problem remains?
2. What evidence supports solving it now?
3. Does the change use truthful, user-owned data rather than synthetic engagement?
4. What privacy, security, accessibility, or failure-state risk does it introduce?
5. What is the smallest complete solution?
6. How will its behavior and visual quality be verified?

A change is not complete when it merely renders. It must have a useful path, honest empty and error states, server authorization where required, mobile accessibility, tests proportional to risk, and updated documentation.
